# Next.js 16 notes for this repo

Distilled from the docs bundled at `apps/web/node_modules/next/dist/docs/` (Next 16.3.8). Read the
source guide before relying on anything here; it wins on conflict.

## Proxy (formerly middleware)
- File is `src/proxy.ts`, exporting `proxy` (or a default export). The `middleware` name is deprecated.
- Proxy always runs on Node.js. Setting `runtime` throws.
- Without a matcher it runs on every request. Exclude `_next/static`, `_next/image` and public assets.
- Use Proxy for **optimistic** auth only. Re-verify the session in a data-access layer, in every
  Server Action and in every Route Handler.

## Request APIs and caching
- `cookies()`, `headers()`, `draftMode()`, `params` and `searchParams` are **async only**.
- Use the global `PageProps<'/route'>`, `LayoutProps<'/route'>` and `RouteContext<'/route'>` types.
  They are generated by `next typegen`; our `typecheck` script runs that first.
- `fetch` is uncached by default. To cache, opt in with `cache: 'force-cache'` or `'use cache'`.
- With `cacheComponents: true`:
  - Everything is dynamic by default. Opt into caching with `'use cache'` plus `cacheLife` and
    `cacheTag` from `next/cache`.
  - Runtime reads must be inside `<Suspense>`.
  - The `dynamic`, `revalidate` and `fetchCache` segment configs are removed.
- `revalidateTag(tag, profile)` requires the second argument. Use `updateTag` inside Server Actions.

## Config
- `typedRoutes` is a top-level option (enabled here).
- Turbopack is the default for dev and build. A custom `webpack` config breaks `next build`.
- Turbopack transpiles workspace packages (`@sg/*`) automatically. `transpilePackages` is only
  needed for npm packages that ship raw TS.
- `output: 'standalone'` needs `outputFileTracingRoot` set to the repo root, and `public/` plus
  `.next/static` copied in.
- `next lint` is removed. Run the ESLint CLI with flat config instead.

## Client-only libraries (three.js / R3F)
- `next/dynamic(..., { ssr: false })` is **not allowed in Server Components**. Wrap it in a
  `'use client'` component and render that wrapper from the server.

## Env
- `NEXT_PUBLIC_*` values are inlined at build time. Everything else is server-only.
- `.env*` files go in the app root (`apps/<app>/`), not in `src/`.
