# ElevenLabs agents as code

Every Skill Garden voice character is defined here and synced to ElevenLabs with the official
[`elevenlabs` CLI](https://github.com/elevenlabs/cli) (pinned at 1.4.0 in the root
`package.json`). You edit small YAML specs and markdown prompts; `sg-agents build` compiles them
into the raw configs the CLI pushes, validated offline against the ElevenLabs API schema.

## Layout

```
agents/
  characters/<key>/agent.yaml     voice, LLM, turn-taking, tools, data collection, evaluation, workflow
  characters/<key>/prompt.md      base system prompt
  characters/<key>/phases/*.md    one prompt per workflow phase (subagent node)
  shared/guardrails.md            appended to every prompt
  tools/*.yaml                    server (webhook) and client tools
  tests/<key>/*.yaml              ElevenLabs agent tests: llm, tool and simulation
  dynamic_variables.yaml          every {{variable}} agents may use, with test placeholders
  environments.yaml               API base URL that server tools call, per environment
  voices.yaml                     Voice Design prompts, one per character
  voices.json                     designed voice IDs (written by `sg-agents voices create`)

  # generated by `sg-agents build`; never edit by hand
  agent_configs/  tool_configs/  test_configs/
  agents.json  tools.json  tests.json   CLI registries; the CLI writes remote IDs here on push
```

## Everyday commands (from the repo root)

```bash
uv run sg-agents build            # compile and validate; writes generated files
uv run sg-agents build --check    # CI: fail if generated files are stale (also a pytest)
uv run sg-agents sync             # build, then push tools, tests and agents in dependency order
uv run sg-agents test [drona ...] # run attached ElevenLabs agent tests
uv run sg-agents ids              # JSON for the API's ELEVENLABS_AGENT_IDS
```

All commands read `ELEVENLABS_API_KEY` from the root `.env`. `build` needs no key.

## First-time setup

1. Put `ELEVENLABS_API_KEY` in the root `.env`.
2. Design the voices. For each character, generate three previews, listen, and keep one:
   ```bash
   uv run sg-agents voices design --all          # previews land in agents/.voice-previews/<key>/
   uv run sg-agents voices create drona --preview 2
   ```
   `voices.json` records each voice ID with the seed and prompt hash that produced it.
3. Set `api_base_url` for `dev` in `environments.yaml` once the API is deployed (C05).
4. `uv run sg-agents sync`. The first push creates every tool, test and agent; the CLI writes
   their IDs into the registries. **Commit the registries**: later pushes update in place, and
   CI refuses to create resources (`--update-only`).
5. Set `ELEVENLABS_AGENT_IDS` in the API environment from `uv run sg-agents ids`, and
   `AGENT_TOOL_TOKEN_SECRET` to a random 48-byte string.

## How a session connects

1. The browser calls `POST /v1/sessions {character, focus_concept_id?, persona_tone?}`.
2. The API builds the briefing, fetches a WebRTC conversation token for the private agent
   (`GET /v1/convai/conversation/token`), and mints a signed tool token bound to the learner,
   session, character and conversation ID.
3. The browser calls `startSession({ conversationToken, connectionType: "webrtc",
   dynamicVariables })` with the returned values.
4. Server tools call `POST <api>/v1/agent-tools/<name>` with the tool token in
   `X-SG-Tool-Token` (from the `secret__sg_tool_token` variable, which the LLM never sees) and
   `conversation_id` filled by ElevenLabs. Tool routes verify both with
   `require_tool_token` and `check_conversation` from `sg_api.sessions.tool_tokens`.

Client-sent dynamic variables are not trusted for authorization, and every client override is
disabled. See [ADR 0001](../docs/adr/0001-private-document-isolation.md).

## Adding or changing things

- **Prompt change:** edit the markdown, run `uv run sg-agents build`, commit sources and
  generated files together, then `sg-agents sync`.
- **New tool:** add `tools/<name>.yaml` (`webhook` tools need `path: /v1/agent-tools/<name>`),
  list it under a character's `tools` or a phase's `tools`, and build. The API route belongs to
  the component that owns the data.
- **New dynamic variable:** declare it in `dynamic_variables.yaml` and set it in
  `POST /v1/sessions` (`sg_api/sessions/router.py`). The build fails on undeclared variables,
  and a test checks the endpoint sets every declared one.
- **New test:** drop a YAML file in `tests/<character>/`; it is compiled, pushed and attached to
  that agent automatically.
- **Schema refresh** after bumping the CLI:
  ```bash
  pnpm exec elevenlabs agents create --spec-raw > /tmp/spec.json
  uv run sg-agents schema refresh /tmp/spec.json
  ```
